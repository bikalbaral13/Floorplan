id: verify-trace-overlay-and-areas
name: Prove the trace overlays and measures before reporting
category: Floorplan Tracer
when: A traced plan JSON exists and you are about to hand it over — every time, even after a one-line correction.
tools: [Bash, Read, get_state, list_spaces, snapshot_canvas]
requires: [author-plan-graph-in-image-pixels]
---

Four checks, cheapest first. Each catches a different failure; skipping one is how a plan that "looks right" ships with a bedroom 8 % too small, a door hinged on the wrong jamb, or three sliver rooms the user has to delete.

1. **Label dimensions vs printed dimensions** (numbers, from the build script's replay of the editor's inset rule). Every room with a printed L×B must predict EXACTLY — `Δ 0.000 / 0.000 ft` — because the wall lines were solved from those numbers; anything else is a wrong half-thickness in the solve or a ring edge picking up a thicker collinear band than you assumed. Then areas: every room with a printed L×B should be within ±2 % once the scale is right. A room off by 3–5 % while the rest are exact means the printed size was taken to a different face than the drawn one (both toilets on Windsor Park: −3.2 % and −4.8 %, the printed 8'×5' does not fit between the drawn faces at any scale) — report it, do not bend the wall. A room off by 8 %+ is a mis-measured face or a wrong constant; fix the build script. Rooms with no printed size (duct, niche, shafts) are sanity-checked against neighbours.
2. **Headless bake** (`node tools/bakeplan/run.mjs plan.noimg.json --out baked.json`, run from the app repo). It fetches every distinct `objectPath` from the Library bucket, evaluates every attachment and writes its meshes AND its `plan2d` fills. Read the summary: `library: N/N objects resolved`, `attachments N   with meshes N`. An unresolved path is a typo in `objectPath`; an empty door is usually a `width` the object cannot fit into its host piece. Opening pieces must show `0` meshes and ONE attachment each — a second attachment there is a Wall object that will fill the gap in 3D.
3. **Overlay proof from the bake** (a picture you can read, before touching the app). Composite onto the image at 2×: wall bands from the plan segments as filled red rectangles of their real thickness, dashed boundaries orange, spaces as green outlines with their label, and — this is the part that catches rotation and hinge errors — every attachment's baked `plan2d.fill` polygons drawn at `anchor + point` (metres, y-down, ×ppm, +W/2,H/2): doors orange, windows blue, everything else magenta. Then LOOK, per room at 2–4×: does every red band sit on a brown band? is every 90° corner two bands meeting at one node with nothing poking past it? do the two wall ends at each leaf-less opening stay square (a wedge means a thin line was used instead of an opening piece)? does every door / window / opening whose end meets a perpendicular wall reach it through a short wall stub (an opening band ending on a T node draws a gap there)? does each door's baked arc lie on the printed arc (same centre, same side)? do the bed's pillows, the toilet's cistern and the sofa's back sit where the render draws them? Anything that does not is an input coordinate or a `rotation` / `swing` — fix it in the build script and rebuild. Do not judge a door from a small crop: at 2× the leaf line and the arc are easy to swap; crop the door at 4× before deciding it is wrong.
4. **In-app import through the app's OWN importer** (the user's workflow). Open the editor with `?agent=1` so the MCP bridge answers, upload the plan to `library/Designs/<name>.json` with `putObject`, then hand the file to the editor's hidden `.json` file input from page JS — `fetch` the public R2 URL, wrap it in a `File`, set `input.files` through a `DataTransfer`, dispatch `change` (snippet in `floorplan-tracer-scripts`). That runs `fromStandardPlan` exactly as a drag-and-drop would: settings (ppm), underlay, layers, object resolution by `objectPath`. **Do not use `apply_model` for this check** — it merges the internal model and skips all of that (ppm stays 50, no underlay, every object draws as the staircase placeholder), so it proves nothing. Then read `get_state` (ppm = the calibrated value, `objectsLoaded` = every kind you used) and `list_spaces` (every manual label with the build script's area, and NO `Space00N` auto-rooms — a sliver there is an open polyline touching a wall) and take a screenshot with the underlay at ~55 %. Toggle the Image layer off and screenshot again — the plan must read as a complete drawing on its own.

Send the overlay proof and the in-app screenshot to the user with the numbers from step 1. Report in two or three sentences: scale, residual, area deltas, guesses. The JSON is the deliverable; the pictures are the evidence that it is right.
